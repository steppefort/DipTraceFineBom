# Перевірка FineBOM 0.1.1

[English](VALIDATION.md) · Українська · [README](../README_UA.md)

На Linux успішно виконано 19 тестів, зокрема інтеграційний запуск через справжній
Python-процес керування DipTraceSchPluginAdapter. Залежність адаптера закріплена
за комітом `02685a4e96f258a22215e9a8e40f0c73827acfdc`.

Інтеграційний тест перевіряє маніфест FineBOM, хеші кожного скопійованого файлу
адаптера, вибір успадкованих змінних, один ODS на запуск, окрему діагностику,
незмінність вхідного XML і передавання помилок робочого процесу до `status.json`
адаптера.

Тести обробника BOM охоплюють порядок позначень, фільтри складання, багатосекційні
компоненти, групування за точним Value, конфлікти полів, заміни, відсутні змінні
та некоректні вхідні дані. Перевірки результату охоплюють збіги імен файлів,
підстановку Company, текст дати й часу, чергування рядків, межі та збереження
параметрів сторінки з порожнім верхнім колонтитулом і динамічними полями номера
та кількості сторінок унизу.

Для FineBOM 0.1.0 окреме порівняння з наданим обробником BOMJob Python 0.2.7 використовувало ту саму
синтетичну схему, налаштування, час і типовий OTS-шаблон. Обидва результати
містять 7 компонентів у 4 групах із 2 конфліктними позначеннями. Вміст архівів
OpenDocument збігається з урахуванням нової назви й версії генератора,
ідентифікаторів створених стилів і перекладу приміток про конфлікти.

Типовий шаблон скопійовано без змін. Його SHA-256:

```text
21a5fa078c1e8f63e560baf32348ca9a123b97828314baa68195e3f62e6f28b1
```

Ці перевірки не запускають Windows EXE усередині DipTrace. Установлення,
нативний запуск, успадкування змінних від справжнього процесу DipTrace та
вигляд друку потрібно також перевірити у Windows. Приватні захоплення схем
до тестів репозиторію не включено.

Інтеграційний тест 0.1.1 також перевіряє назву з версією, обидві версії
контексту, записи журналів, поля звіту та метадані генератора ODS. Змішані
версії коду й конфігурації відхиляються до створення каталогу результатів.
