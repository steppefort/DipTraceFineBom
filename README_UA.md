# FineBOM

[English](README.md) · Українська

**Створення оформленого переліку компонентів OpenDocument зі схеми DipTrace.** FineBOM заповнює табличний шаблон `.ots` полями компонентів і змінними проєкту, групує компоненти за Value та зберігає `.ods` у папці `Docs` проєкту.

Типовий шаблон [`templates/BOM.ots`](templates/BOM.ots) входить до комплекту. Його можна відредагувати в LibreOffice Calc відповідно до оформлення вашої документації.

FineBOM — Python-плагін із прямим використанням [DipTraceSchPluginAdapter](https://github.com/steppefort/DipTraceSchPluginAdapter). Він також є повним прикладом плагіна, побудованого на публічному API контексту адаптера. Окремого нативного засобу запуску FineBOM немає.

Версія **0.1.1** · Python **3.11+** · засіб запуску Windows x64 · ліцензія MIT.

## Версія та залежність адаптера

FineBOM **0.1.1** використовує DipTraceSchPluginAdapter **0.1.1**, API **1**,
коміт `02685a4e96f258a22215e9a8e40f0c73827acfdc`
(тег випуску `v0.1.1`). Це незалежні версії двох продуктів.

`finebom/build_info.json` — єдине джерело версії FineBOM.
Її читають Python-пакет, метадані генератора ODS, звіт та інструмент збірки.
Збірка передає цю версію генератору плагінів адаптера та записує її до
`[plugin] version` у встановленому `adapter.ini`. Назва в меню — **FineBOM 0.1.1**.
`FineBOM.exe`, `plugin_id` та шлях до захоплень залишаються сталими.

EXE адаптера та папка `.adapter` надходять із закріпленого коміту без змін.
Властивості EXE у Windows і команда `FineBOM.exe --version` показують версію
**адаптера**. `report.json` містить окремі поля `plugin_version` і `adapter_version`.
Робочий процес відхиляє змішані версії коду плагіна та конфігурації.

Для оновлення встановленої копії замініть повну папку `FineBOM` і перезапустіть
DipTrace Schematic Capture. Збережіть власні налаштування `finebom.ini` та шаблони.
Використовуйте новий `adapter.ini`, щоб його версія плагіна відповідала коду.

## Встановлення та запуск

1. Отримайте готову папку `FineBOM` або зберіть її з вихідного коду за інструкцією нижче.
2. Скопіюйте всю папку, включно з `.adapter`, до `Plugins\Schematic` у каталозі встановлення DipTrace. Типовий шлях: `C:\Program Files\DipTrace\Plugins\Schematic\FineBOM`.
3. Установіть Python 3.11 або новіший. Додаткові Python-пакети не потрібні. У `adapter.ini` залиште `executable = py.exe`, якщо цей засіб запуску доступний, або вкажіть абсолютний шлях до свого `pythonw.exe` без лапок.
4. Перезапустіть DipTrace Schematic Capture. Відкрийте збережений проєкт і виберіть **Tools > Plugins > FineBOM 0.1.1**.
5. Перевірте створений `.ods` у папці `Docs` проєкту. Python завершується автоматично, консоль і папка захоплення не відкриваються.

Типове ім’я файлу — `<projectname>v<revision>bom<datetime>.ods`, наприклад `Board01v2bom06.09.2026_21-20.ods`. Задайте `projectname` і `revision` у **Tools > Environment variables** DipTrace або явно вкажіть резервні значення в INI. Для сумісності з Windows у часовій частині імені замість двокрапки використовується дефіс. У разі збігу імен додаються `_2`, `_3` тощо, попередні BOM зберігаються.

Установіть `[plugin] open_result = true` у `finebom.ini`, щоб відкривати готовий BOM у програмі, пов’язаній із `.ods` у Windows.

## Збірка з вихідного коду

Репозиторій містить прикладний код і типовий шаблон. Інструмент збірки отримує **закріплений коміт** DipTraceSchPluginAdapter та використовує його власний `tools/new_plugin.py` для створення встановлюваної папки.

У PowerShell із робочого каталогу розробки:

```powershell
git clone https://github.com/steppefort/DipTraceFineBom.git
cd DipTraceFineBom
py -3 tools/build_plugin.py
```

Якщо ви завантажили архів вихідного коду, розпакуйте його й виконайте останню команду з кореня. Git усе одно потрібен для отримання залежності адаптера.

Команда:

1. Читає `adapter-dependency.json`, отримує вказаний коміт адаптера до `.cache` та перевіряє коміт і контрольну суму EXE.
2. Викликає генератор адаптера з `--name FineBOM --mode job --plugin-version 0.1.1`.
3. Додає код, налаштування, шаблон і документацію FineBOM до створеної папки.
4. Установлює назву в меню DipTrace **FineBOM 0.1.1**, зберігає службові модулі адаптера та фіксує залежність у `adapter.lock.json`.
5. Створює **`build/FineBOM`**. Для встановлення скопіюйте всю цю папку до DipTrace.

Компілятор C не потрібен: коміт адаптера містить готовий Windows EXE. Команда не вбудовує й не встановлює Python. Каталог призначення ще не повинен існувати. Для наступної збірки виберіть новий:

```powershell
py -3 tools/build_plugin.py --dest build/FineBOM-next
```

Для збірки без мережі вкажіть чисту локальну копію точного закріпленого коміту адаптера:

```powershell
py -3 tools/build_plugin.py --adapter-source D:\src\DipTraceSchPluginAdapter --dest build/FineBOM-offline
```

На Linux працює та сама збірка через `python3 tools/build_plugin.py`, результат також призначений для Windows. Закріплений адаптер не підтримує нативний запуск у macOS.

Для оновлення залежності виберіть перевірений коміт адаптера й оновіть `version`, `tag`, `commit` та `exe_sha256` у `adapter-dependency.json`. Створіть новий пакет і виконайте тести. Залежність оновлюється під час розробки чи пакування, а не під час запуску плагіна в DipTrace.

## Як працює інтеграція

| Файл або каталог                                   | Відповідальність                                                                                                     |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| [`plugin.py`](plugin.py)                           | Публічна точка входу `main(ctx)`, викликає обробник FineBOM і повертає успіх. Винятки передаються адаптеру.          |
| [`finebom/workflow.py`](finebom/workflow.py)       | Читає захоплений XML і вибрані змінні через `ctx`, визначає шляхи результатів і записує діагностику в `ctx.run_dir`. |
| [`finebom/core.py`](finebom/core.py)               | Читає компоненти схеми, групує їх і заповнює шаблон OpenDocument.                                                    |
| [`finebom/output.py`](finebom/output.py)           | Формує допустимі імена та зберігає результати без перезаписування попередніх BOM.                                    |
| [`finebom/page_labels.py`](finebom/page_labels.py) | Налаштовує колонтитули й поля нумерації сторінок.                                                                    |
| `finebom.ini`                                      | Налаштування BOM і правила замін.                                                                                    |
| `adapter.ini`                                      | Версія API адаптера, режим `job`, виконуваний файл Python і точка входу.                                             |
| `adapter-dependency.json`                          | Репозиторій адаптера, закріплений коміт, версія API та контрольна сума EXE для збірки.                               |
| `build/FineBOM/.adapter`                           | Незмінені службові модулі, скопійовані генератором адаптера, це не реалізація FineBOM.                               |

FineBOM використовує `ctx.read_xml()`, `ctx.environment(names)`, `ctx.project_dir`, `ctx.plugin_dir`, `ctx.run_dir`, `ctx.exchange_path` та `ctx.log()`. Він ніколи не викликає `ctx.commit_xml()`. Створений маніфест містить `ExpMode=All` та `ImpMode=None`.

Адаптер відповідає за каталоги захоплення, створення процесів, вибір успадкованих змінних і стан виконання. FineBOM не запускає старий консольний обробник BOMJob, не читає його `capture.json` і не реалізує власний засіб запуску. Уся логіка BOM — звичайний Python-код.

Для іншого плагіна зберігайте цей розподіл: отримуйте контекст запуску від адаптера, реалізуйте завдання у власному пакеті й завершуйте `main(ctx)` після виконання. Роботу UI та повернення змін описано в [API адаптера](https://github.com/steppefort/DipTraceSchPluginAdapter/blob/main/docs/API_UA.md).

## Правила шаблона

Створіть один рядок шапки з `@RefDes`, `#Value` та `$Quantity`. Інші поля можуть розташовуватися в довільному порядку в тому самому рядку.

| Маркер                                        | Поведінка                                                                                                                              |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `@RefDes`                                     | Перелічує позначення компонентів в одній комірці через кому. Інші поля `@` також об’єднують значення.                                  |
| `#Value`                                      | Визначає значення для групування. Компоненти з точно однаковим початковим Value за замовчуванням займають один рядок BOM.              |
| Інші поля `#`                                 | Беруть значення першого компонента. Відмінності наступних компонентів ігноруються для цього поля, а їхні RefDes позначаються червоним. |
| `$Quantity`                                   | Рахує всі включені компоненти групи, зокрема з конфліктними полями.                                                                    |
| `<projectname>`, `<Company>` та інші `<name>` | Замінюють увесь токен відповідним значенням середовища без урахування регістру. Імена автоматично визначаються з шаблона.              |
| `<datetime>`                                  | Використовує поточний локальний час, типовий формат у комірці — `YYYYMMDD HH:MM`. Це не змінна середовища.                             |

Префікси маркерів видаляються зі створеної шапки, дані починаються нижче. Одразу під шапкою розмістіть один або два порожні оформлені рядки-зразки. За `template_rows = auto` два різні зразки чергуються в усіх створених рядках. Заливки та межі зберігаються. `template_rows = 1` або `2` явно задає їхню кількість.

Типова поведінка друку копіює розмір паперу, орієнтацію, поля й масштаб із шаблона, верхній колонтитул порожній, унизу по центру розміщуються поля **Page N from M**. Для збереження початкових колонтитулів шаблона задайте `[print] header_footer = template`.

Об’єднані комірки в рядках-зразках BOM, формули нижче шапки й іменовані діапазони, на які впливає вставка рядків, не підтримуються. FineBOM повідомляє про такі випадки, щоб не створювати документ із пошкодженими посиланнями.

## Відбір і порядок компонентів

За замовчуванням включаються лише компоненти з Part Type **Normal** або **Tip** та полем `ASM`, рівним **Y**, **YES** або **TRUE**, без урахування регістру. Вимкнені компоненти виключаються. Кілька секцій одного компонента рахуються один раз.

Типовий порядок позначень — `A,C,R,L,D,DA,DD,D*,VD,VT,*`, із числовим сортуванням у межах префікса (`C2` перед `C10`). `D*` охоплює решту префіксів, що починаються з D, `*` розміщує інші префікси за абеткою. Порядок груп визначається першим включеним компонентом кожної групи.

Секції замін на кшталт `[replace:01]` виконуються в порядку файлу. Підтримуються режими `exact`, `literal` та `regex`. `fields` приймає імена полів через кому, `*` або `env:author` для заміни значення середовища в шаблоні. За замовчуванням заміни впливають на виведення та порівняння, але не об’єднують різні початкові Value. Увімкніть `group_after_replacements = true`, лише якщо групування має використовувати перетворені Value.

## Налаштування та змінні середовища

Редагуйте встановлений `finebom.ini`. Ключі BOM, сортування, замін і друку відповідають BOMJob 0.2.7, але файл налаштувань тепер називається `finebom.ini`, а необов’язковий файл резервних значень проєкту — **`finebom.project.ini`**.

| Параметр                        | Типове значення та призначення                                                                                                                     |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `[plugin] template`             | `templates/BOM.ots`, відносно каталогу INI.                                                                                                        |
| `[plugin] output_dir`           | Порожнє: каталог проєкту з адаптера. Відносний перевизначений шлях починається поруч з INI.                                                        |
| `[plugin] output_subdir`        | `Docs`, відносна папка без `..`. Порожнє значення зберігає безпосередньо в базовому каталозі.                                                      |
| `[plugin] environment_file`     | Необов’язковий явно вказаний INI із секцією `[environment]`.                                                                                       |
| `[plugin] filename_pattern`     | `<projectname>v<revision>bom<datetime>.ods`.                                                                                                       |
| `[format] timestamp_format`     | `%Y%m%d %H:%M` усередині таблиці.                                                                                                                  |
| `[environment_options] missing` | `keep` залишає відсутні токени видимими й додає їх у звіт, `error` не створює результат. Відсутність змінних імені файлу завжди зупиняє генерацію. |

У каталозі результатів залишаються лише завершені `.ods`. Звіти, дані компонентів і журнали зберігаються в каталозі запуску адаптера. Якщо вказаний каталог проєкту недоступний, генерація завершується помилкою без перенаправлення результату. Якщо ProjectDir порожній, результат записується в `Docs` усередині каталогу запуску, про що додається повідомлення в журнал.

Пріоритет змінних, від найвищого до найнижчого:

1. Контейнери змінних середовища в XML, якщо вони є.
2. Значення, повернені `ctx.environment()` адаптера.
3. Файл із `[plugin] environment_file`.
4. `<каталог проєкту>/finebom.project.ini`, секція `[environment]`.
5. `[environment]` у `finebom.ini`.

Адаптер читає успадковані значення процесу, а не постійні системні налаштування Windows. Зберігаються лише запитані імена. FineBOM не створює та не редагує змінні в DipTrace. Старі знімки `environment.json` автоматично не використовуються.

## Діагностика та ручне відлагодження

Кожен запуск має каталог у `%LOCALAPPDATA%\DipTraceSchPluginAdapter\FineBOM\captures`. `latest.json` указує на останній. Для зміни розташування задайте `capture_dir` в `adapter.ini`.

Перевіряйте `ok` або `error` у `status.json`: EXE може завершитися раніше за фонове завдання. `plugin.log` містить перебіг роботи й помилки, а `worker.log` — виведення Python. FineBOM додає `report.json` та `components.json`. Вибрані успадковані змінні містяться в `selected_environment.json`.

Для відлагодження зберіть плагін і запустіть процес керування адаптера з копією захопленого XML:

```powershell
$env:projectname = 'ExampleProject'
$env:revision = '1'
$env:Company = 'Example Company'
$env:author = 'Example Engineer'
$env:root_proj = 'Main'
py -3 build/FineBOM/.adapter/host.py --config build/FineBOM/adapter.ini --exchange D:\Test\exchange.xml
```

Це створює нове захоплення адаптера й виконує ту саму точку входу `main(ctx)`. Відкрита схема DipTrace не змінюється. Змінні початкового процесу не успадковуються автоматично пізнішою оболонкою, передайте їх явно, як у прикладі, або через налаштований резервний INI. Для відтворення Windows-захоплення на Linux установіть `[plugin] output_dir` у доступний локальний каталог.

## Тести

Спочатку зберіть плагін, потім виконайте:

```powershell
py -3 tools/build_plugin.py
py -3 -m unittest discover -s tests -v
```

Якщо збірка вже існує, виконайте лише команду тестів. За потреби вкажіть іншу готову папку через `FINEBOM_TEST_PLUGIN`. Тести охоплюють відбір, секції компонентів, групування, позначення конфліктів, заміни, пріоритет змінних, імена файлів, повторне збереження, оформлення й запуск через справжній Python-процес керування адаптера. Дані тестів синтетичні, приватні захоплення схем не поширюються.

Тести працюють на Linux і Windows. Перевірка Windows EXE, запущеного з DipTrace, та візуальна перевірка друку BOM потребують установленого DipTrace у Windows.
